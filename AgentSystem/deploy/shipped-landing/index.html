1) Origin

FixMyY is where the product run started.

FixMyY

Live

A facilities-management app built from real YMCA maintenance work.

The problem was simple and immediate: keep work orders, PM schedules, and equipment records usable in one working system. FixMyY solved it with a React + Supabase app and AI-assisted work-order intake tied to day-to-day maintenance operations. One major hurdle was a recursive RLS policy issue in org membership that had to be fixed in migration history before the system stabilized.

Outlook: FixMyY stands as the operating blueprint for future field-service products that need practical, maintenance-first workflow control.

Open fixmyy.com

4) Cold storage

Shipped systems that were intentionally stopped, with backups preserved.

AgentLooper

Cold storage, backups kept

A platform that evolved from learning-loop service to storefront and local-jobs flow.

AgentLooper had to support changing needs across multiple phases: recursive learning service, security-tool commerce, and quote-to-close workflow support. It solved that by adapting one platform to several product jobs over time. Its biggest hurdle was preserving operational safety as product identity shifted, especially across payments and fulfillment boundaries.

Outlook: AgentLooper’s architecture remains a strong relaunch base for modular autonomous-service products.

ProofChain

Cold storage, backups kept

A trust layer for agent identity, receipts, and compliance evidence.

Autonomous systems needed a clear way to prove who acted, what changed, and whether it was authorized. ProofChain solved that with identity primitives, verifiable receipt flow, and compliance-facing interfaces built as an open-core stack. Its hardest hurdle was market timing and positioning, not technical execution, leading to a controlled pause with full backups retained.

Outlook: ProofChain’s verifiable receipt architecture is ready to power future accountability features in active agent products.

Dead Air FM radio

Cold storage, backups kept

An internet radio stack with automation, interaction, and generated host segments.

Running an always-on station required scheduling, stream metadata, listener requests, and generated break content working in one coordinated pipeline. Dead Air solved that with a full broadcast pipeline including stream engine, metadata flow, and interaction APIs. The recurring hurdle was keeping now-playing and vote/request state in sync with live output under constant uptime pressure.

Outlook: Dead Air’s broadcast engineering can be carried directly into the next live audio project when that channel returns.

5) Open-source agent frameworks

Public engineering systems that support product and automation work.

AgentSystem

Open source

Distributed orchestration for edge-ready agent workloads.

Teams needed a way to coordinate multi-worker agent execution across distributed hardware and model providers. AgentSystem solved that with queue-driven orchestration patterns designed for practical edge deployment. A central hurdle was keeping complex integration surfaces maintainable as the system expanded.

Outlook: AgentSystem is maturing into a durable orchestration core for production agent fleets.

Open GitHub repo

EBAIF

Open source

A framework for emergent behavior patterns in AI systems.

Static behavior models often break when environments change quickly. EBAIF solved that by exploring behavior genomes, consensus mechanics, and adaptive evolution paths in one framework. Its core hurdle was translating ambitious emergent-behavior design into reusable modules others can adopt directly.

Outlook: EBAIF can become the adaptive-behavior layer plugged into future autonomous game and agent systems.

Open GitHub repo

AgentSDK

Open source

A Python SDK for autonomous agents and benchmark workflows.

Builders needed a repeatable way to stand up autonomous workflows without rebuilding common primitives every time. AgentSDK solved that with client libraries, examples, and benchmark-oriented tooling in one package. One hurdle was balancing broad capability with clean public documentation teams can trust and apply quickly.

Outlook: AgentSDK is set to remain the onboarding and implementation bridge for new autonomous builds.

AgentSwarm

Open source

Real-time monitoring and alerting patterns for live data feeds.

High-volume live feeds need fast filtering before they become useful action. AgentSwarm solved that with event-driven monitoring and alert logic tuned for autonomous response patterns. Its hurdle was maintaining broad scope while core product priorities shifted elsewhere.

Outlook: AgentSwarm’s event-ingestion architecture can continue as a reusable foundation for future monitoring products.

THE SYNDICATE

Framework

A swarm architecture with hard handoffs between drafting, gating, and execution.

Autonomous outreach systems fail fast when one agent can draft, approve, and send without control points. THE SYNDICATE solved that by splitting responsibilities across SNIPER drafts, AUDITOR gates with veto authority, and EXO ships. The hardest hurdle was preventing unsafe or low-quality outbound behavior, solved through auditable state-machine flow and explicit pass/fail gates.

Drafts are checked and approved before anything ships, so outbound actions stay deliberate, reviewable, and controlled.

Outlook: THE SYNDICATE is poised to become a reference operating model for governed autonomous outbound systems.

redteam

Security operators needed reproducible probing workflows instead of ad-hoc model poking. redteam solved that with tool-first diagnostics, structured output, and automation-friendly execution. The main hurdle was keeping open-source evolution aligned with live product reliability expectations.

Outlook: redteam remains the open implementation layer that strengthens the live REDTEAM product path.

6) Experiments and concepts

Games and experiments.

fleet kernel

Experiment

A governance concept for registry, trust levels, loop brakes, and kill-switch control.

As autonomous fleets grow, operators need hard controls over identity, trust progression, and emergency shutdown behavior. fleet kernel addresses that problem as an architecture concept spanning registry, message board, ledger, trust laddering, loop brakes, and kill-switch controls. The hurdle was designing a governance model strict enough for real incidents while preserving enough flexibility for normal autonomous operation.

Outlook: fleet kernel can graduate into a concrete control-plane implementation that anchors safe multi-agent operations.

Sol Horse

Experiment

A horse-racing sim game project with genetics, training, and tournament systems.

The project aimed to combine progression gameplay with simulation depth in one racing experience. Sol Horse solved that by connecting breeding, training, and competitive loops in a playable architecture. A clear hurdle was deployment continuity, since public release status changed while core game systems continued evolving.

Outlook: Sol Horse remains a strong foundation for a future racing-sim relaunch.

DeckWizard

Experiment

A blackjack probability bot surfaced as a live web demo.

Players needed fast, understandable probability guidance without digging through strategy tables. DeckWizard solved that with an interactive decision-support interface tied to live demo usage. The hurdle was deciding how to keep the tool lightweight and useful while preserving room to reuse its interaction patterns in larger products.

Outlook: DeckWizard will continue as a polished utility demo and design reference for future interactive assistants.

Open deck-wizard demo

AgentCasino

Experiment

An AI-run casino-games experiment for autonomous gameplay loops.

The experiment explored whether autonomous agents could participate in shared casino-style game loops with real-time interaction. AgentCasino solved that by pairing game mechanics with a controlled AI-participant environment. Its main hurdle was intentionally keeping the project in R&D mode rather than forcing premature production rollout.

Outlook: AgentCasino remains a focused testbed for agent-native gameplay and economic simulation design.
